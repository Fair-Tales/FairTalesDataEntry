| Input tokens | 173.11 million | 36,065/minute | 2 million ITPM |

These are arithmetic averages, not load tests. Even the quota-only ideal lower bound is about 87 minutes for input, 44 minutes for requests and seven minutes for output; actual runtime is much longer because requests take time and stages depend on one another. At five seconds, an 80-hour monthly window is plausible; at ten it is insufficient for one serial worker. Measure latency and schedule longer unattended windows or bounded concurrency through the shared scheduler, not duplicate ad hoc workers.

**Conclusion:** supplied Anthropic rates do not prevent 531 baseline run-equivalents/month. They do not guarantee 531 new, verified books, or bound richer tasks' output usage. Use account-wide request/input/output admission, maximum-output reservations where the provider uses them, bounded concurrency and backoff; start below 10% of the supplied tier and increase only from observed usage. Keep shared-model and other-job consumption in the same limiter. Actual per-model applicability and burst behaviour need confirmation.

**OpenAI organisation limits are UNVERIFIED.** After linking, record model access, RPM/TPM, any daily caps, shared model-family limits, concurrency and token-reservation semantics from the organisation Limits view and response headers. ### Firestore: explicit per-book and daily allocations

The project is on **Blaze**: beyond the supplied 50,000 free reads/day, reads bill rather than becoming free API-credit usage. Writes, storage and S3 have separate costs. Current free-write eligibility, reset boundary and regional prices are **UNVERIFIED**; check the Firebase/Cloud billing and quota views before setting a cash estimate. No API allowance pays those bills.

The photo design's code audit gives the following logical counts, including its proposed deduplication, one status window and connector allowance. Let `N` be sources including separators, `P` actual pages, `G` books, `C` chunks, and `n_c` the cumulative source count after each chunk; assume unique admitted pages equal `P`:

```text
reads  = sum(n_c) + 4N + 24P + 25G + 101
writes = 3N + C + 13P + 26G + 109
         + 2 × metadata_API_responses + 3 × worker_API_responses
         + heartbeats, retries, review edits and other variable operations
```

These are **code-derived successful-path estimates**, not service measurements or worst-case ceilings. The 200-source/192-page/eight-book example starts at 6,269 reads/3,417 writes before usage rollups and variable work. For eight 40-page books, eight separators and six chunks, `P=320, N=328, sum(n_c)=1,228`: **10,521 reads/5,467 writes**. Conservatively charging three usage writes for each of 83.45 attempts/book adds about 2,003 writes. The photo design's 8,000/8,000 reservation for eight shorter books cannot be copied unchanged.

## C. A valid provider comparison as the by-product

Once both baseline runs are operationally useful, their comparison adds almost no inference cost: deterministic alignment, scoring and reporting are local. Schema/accounting integration and human interpretation are still real work.

Freeze a paired manifest **before dispatch**: eligible book IDs, image bytes/hash and page order, source text where shared, exact substantive prompt text/hash, conventions, output schema, scorer/overlay versions, stage boundaries, requested model snapshot, generation settings, image settings and failure policy. Use the same prompts and scorer; provider-native envelopes necessarily differ and must be logged. Do not quietly improve one provider's prompts mid-pair. A tuned-provider comparison is a separate labelled experiment. Keep paired baseline volume symmetric; unequal targeted rescue allocations are operational depth, not evidence that one provider wins at equal effort.

Maintain two views:

1. **End-to-end:** both providers start with the same book images. This assesses operational coverage, output differences, latency and cost of their complete pipelines, including each one's OCR.
2. **Controlled language analysis:** both receive the same frozen text and the same task/schema. This isolates character/speaker/addressee analysis from different OCR inputs. Identify whether that text is student reference, reviewed text or an explicitly chosen model draft; it is not automatically gold truth.

Record provider/model per output, not just aggregate totals. Include missing outputs, refusals, truncation, failed attempts and coverage in the denominators; do not report only mutually successful pages. Reuse the versioned field-aware scorer in [comparison.py](../scripts/extraction_eval/comparison.py); retain paired book-level differences and book-cluster uncertainty rather than treating thousands of pages as independent books. Comparison reports remain exploratory on development/operational data.

**New targets need new comparison endpoints.** The existing scorer does not measure dialogue turns or language relations. Before bulk relation extraction, add a versioned comparator that aligns spans by page, text-revision hash and offsets on the shared-text arm, then separately reports span-presence, speaker, addressee and relation-type agreement. Retain unmatched spans, ambiguous identity alignments and abstentions with explicit denominators. For end-to-end outputs with different OCR revisions, use a declared text/span alignment and report failures to align rather than comparing offsets directly. These are agreement/coverage diagnostics until independent reference labels exist; they supply the new review queue without claiming attribution accuracy.

The existing reference supports OCR comparison and **known-positive** character/alias recovery, with reference-quality caveats for other fields. The measured 48% alias-zero figure is **93/195 books in the relevant student-annotation cohort**, not proof that 48% of all 276 books contain no aliases. Agreement, groundedness and dictionary uniqueness cannot establish correct speaker identity, true alias precision or population recall. Shared omissions can produce excellent agreement. Nevertheless, disagreement localizes expensive uncertainty; agreement plus an audit sample helps triage routine review. Report both, without relabelling either as accuracy.

**The existing 40-book paired Anthropic baseline/candidate holdout is untouched.** Preserve its sample, concealment, prompts, scoring and request-reuse design. No GPT substitution, extra arm, monthly review exposure or tuning on those books. A held-out provider comparison needs **its own prospective frozen design**, with population, independent sample, endpoints and analysis chosen before its unblinding; prefer newly acquired untouched books. Routine comparison does not require that extra study. Apply the existing exposure/quarantine registry when building every monthly manifest.

## D. The disagreement dividend

**Make disagreement drive most review time.** A wrong identity assignment can contaminate many speech/language observations; resolving that one case is often worth more than reviewing several routine pages. The valuable unit is a disputed decision with source evidence, not an entire book or an unfiltered list of textual differences.

Rank the queue by likely downstream impact, number of affected occurrences and evidential uncertainty relative to estimated review minutes. Put identity/attachment conflicts and contradictory speaker/addressee assignments first; then missing speech/text, uncertain story inclusion and crop failures; cosmetic variants last. Merge duplicate flags from the same underlying conflict. Show the image/exact text context, anonymized independent answers, the affected inventory counts and any second opinion. Let reviewers confirm, correct or leave unresolved; retain all alternatives, reason, reviewer and time. Keep high-impact unresolved language out of exclusive per-character totals.

Start with **80% of available review time on ranked disagreements and 20% on a random sample of agreements and apparently empty output**. This is a proposed operating split. Random review detects shared errors/omissions and provides a comparator for correction yield. It is not a new full annotation campaign, and these small operational samples do not create a representative benchmark. If time is scarce, review fewer explicit cases and retain unresolved outputs; do not imply that model consensus substitutes for the missing humans.

Track corrections per review hour, language spans affected, unresolved rate, age and failure category separately for targeted and random review. Within a fixed monthly time budget, higher downstream corrections/hour would support the targeted strategy. Disagreement is not guaranteed to find the most errors: providers share training patterns and OCR blind spots, so retain the random component and revise priorities using observed yield. Never extrapolate an enriched queue's error fraction to corpus accuracy. Preserve reviewer corrections as useful operational evidence with their selection mechanism; a future independently annotated study would need a separately frozen sampling and scoring plan.

**Stop all new dispatch for the affected provider immediately** on any unknown price/usage category, unexpected returned model, unrecorded retry, missing cost, credit/auth/billing rejection, duplicate execution, or unexplained provider-versus-local debit. Unknown reporting delay is not a clean reconciliation: keep liabilities and block further exposure when the checkpoint cap is reached.
